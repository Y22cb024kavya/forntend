# Quick Task 260801-003: Enforce Explicit Board and Tone Rendering

**Gathered:** 2026-08-01
**Status:** Ready for planning

## Scope

Integrate the backend terminal route, board policy, interaction metadata, and canonical conversational tone contract into the Flutter chat surfaces without changing the editorial board visual redesign or existing image, save, share, mutation, or offline-sync mechanics.

## Decisions

- Canonical backend route and board policy are the only authority for board rendering. Legacy aliases are data sources only and never override a suppressed route.
- A board response requires an authorized route, an allowed board policy, a valid non-empty map collection, and valid anchor metadata for `style_this`.
- Route policy, safety state, text priority, technical-metadata visibility, and board controls live in one shared response-policy helper.
- `chat.dart` and `ahvi_stylist_chat.dart` use one shared typed Style action-context builder. Visible labels remain presentation only; wire action values and originating request context are preserved.
- Session switches, new chats, clears, and disposal invalidate a generation token. Responses from the same current session remain valid, including concurrent current-session requests.
- Backend conversational text is displayed unchanged when present. Client-authored fallbacks are short, calm, non-technical, and never interpolate raw exceptions.
- Tests use fixtures and mocked/pure helpers only. No backend deployment, network call, or APK build is part of this task.

## Canonical References

- Board-authorized routes: `visual_inspiration`, `wardrobe_style`, `style_this`, `build_outfit`.
- Board-suppressed routes: `style_advice`, `style_pairing`, `missing_pieces`, `supportive_conversation`, `medical_urgent`, `diagnosis_request`, `general_chat`, `clarification`, `error`.
- Required typed actions: `show_visual_inspiration`, `use_my_wardrobe`, `find_missing_pieces`, `style_this`, `build_outfit`.
