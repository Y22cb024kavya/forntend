# Quick Task 260802-001: Strengthen Editorial Board Presentation

**Gathered:** 2026-08-02
**Status:** Implemented and verified

## Task Boundary

Improve the canonical editorial Style board presentation only. Preserve the
response policy, routing, typed actions, Save/Share contracts, image resolver
and provenance rules, interaction permissions, offline-sync behavior,
environment configuration, and APK settings.

## Locked Decisions

- The canonical path remains `VisualDirectionCarousel` ->
  `AhviOutfitBoardCard` -> `EditorialBoardCanvas`; legacy renderers are out of
  scope unless a verified active call path requires compatibility.
- The card keeps a compact fixed height per width and reserves a stable canvas
  height/ratio independent of title, chips, Why It Works, or Styling Tip
  length. Text receives bounded space and action bars remain visible.
- The layout engine remains role-template-driven and preserves the existing
  `BoardItemRole` backend contract. Accessory sub-roles are inferred only from
  existing `accessoryType`, category, subcategory, slot, board role, and name
  metadata; no backend fields are invented.
- Transparent cutout precedence, opaque fallback framing, candidate ordering,
  `expected_transparent`, and `requires_frame` behavior remain untouched.
- Paint-time transforms must be safe inside the canvas. Geometry is clamped
  before rendering, and the canvas remains clipped to its own bounded surface.
- Why It Works and Styling Tip use bounded sentence-safe presentation without
  `TextOverflow.fade`; valid backend copy is not rewritten.
- Existing generic, Style This, and Build Outfit controls, Save, Share, loading,
  and fallback behavior remain unchanged.

## Acceptance Focus

- Three recommendation cards have equal outer and canvas heights.
- Top, bottom, footwear, dress, and outerwear retain clear hierarchy without
  clipping; accessories remain secondary with meaningful bag, belt, watch,
  jewellery, headwear, and scarf placement where metadata permits.
- Narrow and wide board widths remain overflow-free.
- Focused geometry/widget tests cover density, role placement, bounded text,
  controls, loading/fallback geometry, and image provenance.
